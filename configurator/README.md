# Bike Configurator

## Theme Build

Run `npm ci` and `npm run build:configurator` from the repository root after changing the app, data, styling, or model GLBs. The build creates Shopify-ready assets and the generated iframe snippet. Keep these generated files with the theme release.

Run `npm run test:wheel-previews` to validate all configured wheel models: axle centers, chrome/black finishes, retained tire envelopes and ground clearance within 2mm, removal of stock spokes, unchanged hardware transforms, and repeated restoration to stock. It also checks the four Falcon guard shells: lower guards starting within 12mm of the main guard's lower mounting hole, the long bent silhouette with two tapered windows and a rectangular end slot, broad wide-end bands and transverse bridge, lower perimeter alignment within 4mm of outward rail faces in side projection and 6mm in actual 3D distance, molded bridge support within 15mm, absence of small upper pieces, positive volume, watertight edge topology, outward winding, paired inner/outer caps, 8.4-12.4mm modeled depth including edge returns and relief, silhouette/depth bounds, open windows and mounting holes, independent rim/guard selection, and restoration without modifying the original frame. These are modeled dimensions, not measurements of the physical product. Availability, retry, cart revalidation, and responsive layouts must also be checked in the Shopify development preview.

The configurator runs in a same-origin iframe to keep its full-screen styling separate from the storefront. Product options, stock, and prices come from Shopify's product JSON endpoints. Add build to cart rechecks the selected bike-compatible variants and submits one batch to Shopify's Ajax Cart API. Bike and wheelset option details are included on each cart line. A successful submission exposes a shopping-bag link; failures keep the build intact.

## Shopify Access

The `page.configurator` template can be assigned to a Shopify page with handle `configurator`. Until that page exists, the header uses the existing About Us page with `?view=configurator`, which renders the same template. Preview this on a development theme before publishing. Creating static files does not create Shopify page records.

Black Friday messaging announces 15% off automatically at checkout; theme code does not create that discount. Before publishing, verify the automatic 15% discount in Shopify Admin and its combination rules with existing shipping offers. Update any reused discount's old campaign name in Admin. Homepage deal cards show advertised checkout prices; cart and build totals remain Shopify's authoritative prices until checkout.

Black Friday bundles reuse the original Lights + Brakes, Brakes + Frame Guards, and Frame Guards + Wheels product groups with 20% off the second eligible item. The `page.black-friday` template is accessible on the existing Halloween Sale page with `?view=black-friday`, or can be assigned to a dedicated Black Friday page. Enable or rename the matching Shopify Buy X get Y rules before publishing; the bundle offer is separate from the site-wide 15% promotion, and stacking is governed by Shopify's combination rules.

The campaign keeps the storefront's original blue/purple/pink palette, gradient buttons, floating rider visual, and pointer-responsive cards. `assets/black-friday.css` styles campaign components without replacing the base theme tokens or category/bike styling. Check narrow phones, tablets, desktop, landscape, touch input, and reduced-motion mode on the development theme when changing these styles.

### Storefront depth experiment

Theme settings > Storefront experiments > Enable glass and depth UI controls the optional `depth-ui.css` and `depth-ui.js` layer. It is enabled in the development configuration; the schema default is off. Disable it to return to the original restored theme without changing the catalog, campaign, or configurator.

Inspired by Apple's [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) and [Motion](https://developer.apple.com/design/human-interface-guidelines/motion) guidance, glass is reserved for navigation and overlays; prices and product content stay readable. Control magnification is limited to fine hover pointers and respects reduced motion. Glass surfaces respect reduced transparency, increased contrast, and forced colors, with opaque fallbacks in unsupported browsers. The rider image has no magnifier overlay.

## Model Limits

The garage uses a charcoal workshop backdrop, blue/purple accent strips, a branded wall panel, and a flush display pad. Neutral key/fill lighting preserves part finishes; only the key light casts shadows to limit GPU cost. All room details and textures are generated locally, with no external environment downloads.

Rim previews retain the stock tires and wheel dimensions; they are not exact 17-inch wheel-and-tire conversions. Lite and several print-kit assemblies remain visual approximations, not manufacturer CAD or physical fitment certification. Models without configured, previewable parts show Coming Soon. Catalog errors and sold-out variants disable purchase rather than submitting an unverified SKU.

Talaria XXX, MX4, and MX5 have measured per-wheel profiles for the Chrome Talaria XXX/MX3/MX4 Supermoto Wheel Set. These previews replace the rims/spokes while preserving the model's tires and separate rotor/sprocket meshes; XXX's wheel connector is not treated as a wheel. MX4 scan fragments outside the tire width remain in the axle/brake hardware group. The product listing does not certify MX5 fitment, so MX5 is visual-preview-only even if stock returns.

Sold-out catalog variants can be selected with Preview and remain marked as sold out in both the parts panel and build summary, including on mobile. A build containing a sold-out or unconfirmed-fitment part cannot be purchased. Catalog failures still show Retry and never enable preview from missing options; stock is rechecked before any cart submission.

The 79Bike/Ventus Frame Guards product is selectable on Falcon GT, Pro, and Lite in its own Frame guards slot, independent of rims. Its only finish is black, including after switching bikes; there is no color picker or default-title option menu. Paired main-frame and lower guards are independent closed meshes, not copied/recolored bike triangles or double-sided decals. The lower piece preserves the photographed wide bent end, two tapered openings, molded transverse bridge, long body, and rectangular narrow-end slot. Its front begins beside the main guard's lower mounting hole and its rear ends at the swingarm axle; the small upper seat-brace pieces are intentionally omitted. Catalog [molded-part closeups](https://cdn.shopify.com/s/files/1/0745/8013/2068/files/mainframe1.png?v=1785520972), [the full guard set](https://cdn.shopify.com/s/files/1/0745/8013/2068/files/82e4439f-41a0-434e-8aa2-5cbf6331f235.png?v=1785520972), and [installed-bike fitment](https://cdn.shopify.com/s/files/1/0745/8013/2068/files/IMG-2720.png?v=1783612689) guide the silhouettes, broad molded bands, mounting holes, raised rail faces, 1.2mm bevels, and wrapped edge returns. The model uses 6mm extrusion with up to 4mm relief; these photo-inferred proportions are not certified product measurements. The lower perimeter follows outward scan rails within 4mm in side projection and 6mm in actual 3D distance, while molded bridges can span openings with support within 15mm rather than distorting the product into the scan's forked silhouette. The lower shell interpolates depth at the nearest projected outer rail face, with a modeled 0.5mm inner clearance, instead of using the highest corner of each sloping scan triangle. The main shell retains its sampled conservative depth envelope. Missing narrow scan surfaces can interpolate only within 25mm of supported outer faces; unsupported fitting throws an explicit error. Per-model depth bounds exclude inner shock/motor parts and outboard hardware. Bevel normals are calculated at millimeter scale to avoid the utility's 1cm weld tolerance destroying small details. This remains a photo-guided reconstruction, not 1:1 manufacturer CAD; the Lite chassis remains GT-derived. Stock removal reveals the untouched frame. Cart lines retain the selected bike and Black finish and use the live product variant, price, and availability.

Custom Painted/Colored Frame Guards share the same slot and aligned covers on GT/Pro/Lite, replacing rather than stacking on the black guards. The catalog supplies 14 main colors and six effects (84 variants). Main color swatches and separate color/effect selectors choose actual variant combinations and preserve the finish across model switches. Both color-shift palettes respond to viewing angle; automotive clear coat, the two opposite black fade patterns, and angle-responsive iridescent flakes are shader previews. Screen colors, flake scale, and fade placement are approximate, not paint samples. All six painted Black variants are sold out at integration time; live availability is authoritative. Prices vary by effect, production takes up to five business days, and cart properties include the exact Main color and Paint effect. Unknown new catalog finishes show an explicit catalog error rather than silently displaying the wrong paint. Geometry tests cover all 84 finishes on all three models and material cleanup when switching options.

The standalone `python3 server.py` preview does not provide Shopify cart or catalog endpoints. Test purchasing through `shopify theme dev` with mocked cart responses until approving a real cart test. Do not publish or push the theme as part of a local preview.
